# 首次建表与后续登记

## 能力与授权

用户首次明确要求创建投递表后执行；后续以本地配置中的复用授权自动登记指定表。不要因安装了 skill 就创建云资源。新建表默认使用当前已授权飞书账号的私人空间，不更改分享权限、不公开表格。用户指定团队目录时按其目录权限操作。

先读取用户选择的 `tracker.transport`，未选择时询问浏览器或 MCP，不自动按可用工具代选。

- `browser`：通过已登录飞书页面创建、查找和填写表格，不探测、安装或要求配置飞书 MCP，也不要求飞书自建应用。浏览器控制仍使用用户所选 Chrome＋Jev 或 Edge＋Playwright。
- `mcp`：只在初始化或登记时发现当前可用飞书工具。创建多维表格应用、创建数据表/字段，与查询/新增记录是不同能力；安装 MCP 不证明能力齐全。读取实际 tool schema、身份及权限，不复用其他用户的 app_token。
- MCP 缺创建/写入能力或连接失败时，仅在 `allow_browser_fallback: true` 时转浏览器；否则报告缺失能力并保存 `pending_setup` 或待登记项。不得偷偷切换方式。用户后来选择浏览器时复用原表，不另建一份。

任一路径不可用都不阻止可进行的网申填写，不在正常任务中反复要求用户改变已选方式。

应用密钥、访问令牌、刷新令牌通过工具的凭据管理处理，不写入仓库或私人资料。仅把非凭据的表格 ID、链接和字段映射保存到私人状态。

## 首次初始化流程

1. 读取 `tracker-state.json`。`ready` 且目标可访问时直接复用；`ready` 但无权限或表不存在时先报告，不能自动另建一份。
2. 状态缺失时，若用户已配置表格 URL，解析并通过工具确认数据表身份；不要仅靠“求职投递记录”这个常见名称选中别人的表。
3. 确认需要新建后，在本地生成一次 request_id/初始化标识，写状态 `creating`。新建一个多维表格应用及专用数据表；可在新资源描述写入该初始化标识，便于超时后辨认。UI 操作以实际控件为准，不猜按钮名称。
4. 每返回一个远端 ID 立即持久化再进行下一步。平台可能已创建默认数据表，先检查并复用明确属于本次新应用的合适数据表，不再创建重复表。不删除默认表、不清空已有内容、不调整共享权限。
5. 根据下方 schema 建立字段与状态选项，仅在本次专用新表中补齐字段。用户指定现有表时只映射现有字段，结构不兼容则询问具体调整，不擅自改列。
6. MCP 模式读取字段列表一次确认映射；浏览器模式确认表头、状态选项及保存结果。保存 URL、字段映射、timezone 和可获取的 app_token/table_id/view_id/字段 ID；浏览器模式看不到 ID 时可留空，不能为补 ID 强制要求 MCP。状态改为 `ready`，报告可点击链接，之后各申请都使用它。未经验证不报告“表已建好”。

已处于 `creating` 或写入超时：优先用已保存 ID 查询；没有 ID 时按工具支持用初始化标识/返回链接查找。在无法确认上次结果时停下建表，报告不确定状态；不得又新建一份。多个聊天初始化同一配置时由一个聊天完成，其他复用结果；检测本地 `creating` 状态后不争抢创建。

## 默认数据表

表格名默认“求职投递记录”，数据表名默认“投递记录”。名称可配置。

|逻辑键|默认列名|用途/类型|
|---|---|---|
|company|公司名称|招聘页面公司名；文本|
|position|岗位名称|岗位标题，含可见岗位编号；文本|
|location|工作地点|本次招聘地点，多个保留原文；文本|
|applied_at|投递日期|仅实际提交后或用户指定记账口径时填写；日期|
|status|进度|单选：填写中、待提交、已投递|
|job_url|申请链接|本次申请可公开的招聘链接；文本|
|application_key|申请标识|用于复用本次申请的稳定标识；文本|
|recorded_at|记录日期|首次记录当天；日期|

链接不得包含登录 token、临时签名、授权 code 或简历会话密钥；优先存公开岗位链接，没有可安全存储的链接则留空。不要粗暴删除所有参数导致岗位 ID 丢失，必要时仅保存岗位编号。

字段类型和日期序列化以实际工具返回的 schema 为准，不把某个 MCP 的整数 type 常量写死。日期默认使用配置 timezone 的目标日期零点，工具要求毫秒才转毫秒。首次创建只生成结构，不塞虚构投递记录；初始化状态可放本地，不写一行“测试数据”。

## 记录生命周期

以招聘平台＋公司＋岗位 ID（可获取时）及招聘批次建立本地稳定 application_key；缺岗位 ID 时用公司、岗位、地点和用户确认的轮次识别，不能仅按当天日期生成新申请。MCP 返回 record_id 时保存；浏览器模式将申请标识写入对应列，保存表格链接及可获取的记录链接，后续按标识查找同一条，不依赖会变动的行号。

- 未填写完：可保留本地待登记项，或把既有远端记录更新为“填写中”。
- 可编辑内容完成，仍未最终提交：自动新增/更新“待提交”，记录日期为当天，投递日期留空。
- 用户告知已提交，或可靠页面结果表明用户已完成提交：更新“已投递”和实际投递日期，不重复新增。
- 用户明确选择 `status_after_fill: 已投递` 及 `date_on_fill: true` 时允许按其记账口径填写；结果说明仍要区分“记录为已投递”和“网站实际已提交”。

## MCP 登记

仅在用户选择 MCP 时执行。复用已确认字段映射，先按 application_key 或已保存 record_id 定位本次记录；必要时精确搜索公司、岗位和轮次，结果歧义时停止新增，不任意匹配。仅发送本次目标字段，保留其他列与既有实际投递日期。

新增一次，成功后保存 record_id 并回读本条一次作为持久化依据。返回不明先查本次记录再决定是否恢复；鉴权失败不能当“零条结果”。支持幂等请求键的接口，本次重试复用同一个键。

默认由 API 新增，不承诺界面行号或物理末行。用户确实配置 `placement: last_visible_row` 时，先读当前视图排序；若排序决定位置，应说明无法由创建位置保证末行。仅已允许浏览器回退且可确认末尾时，才用浏览器建立末行并用 MCP 补齐；否则说明位置限制，不静默改变视图或方式。不为默认登记滚动整张表。

## 浏览器登记

用户选择 `browser` 时直接使用本节，不先尝试 MCP；或在已允许的 MCP 回退中使用。

复用已保存链接对应的飞书目标表格，确认账号和表名。用表格内查找/筛选按申请标识定位一次；已有则更新，查找完成且无匹配才新增。没有可靠查找结果时不盲目新增，不逐屏扫描整表。

读取当前表头及列顺序，以字段接口或表格支持的多格粘贴成批填写；操作前确认单元格和范围，不能覆盖其他列或已有行。日期与进度按真实控件填写，不把外观文字当选中状态。默认按网站正常新增记录，不承诺行号；配置最后可见行时按视图实际排序和可确认末尾处理。

完成后结束当前单元格编辑，以本条内容和云端保存提示确认持久化，不为每列截图。写入超时先查申请标识，不能再加一行碰运气。

任一方式未确认持久化时，留本地 pending 项并报告待登记，不制造成功状态。下次只补写未完成项，不重放全部历史。切换浏览器/MCP 不改变目标表格或本地申请标识。
