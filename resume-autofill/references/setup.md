# 首次使用与状态恢复

## 一次收集

从用户已经提供的内容提取，不重复询问：

- 简历：本地路径、已附文件或可访问下载链接。
- 照片：可选，本地路径、已附文件或链接。
- 浏览器：`chrome-jev` 或 `edge-playwright`。
- 飞书：首次创建一份多维表格，或复用用户指定的现有表；可指定文件夹。
- 飞书操作方式：`browser`（不接入飞书 MCP，浏览器直接建表和登记）或 `mcp`（使用已接入的飞书 MCP）。选择与招聘网页使用 Chrome/Edge 相互独立。
- 权限：使用所提供资料填写目标招聘网址、上传简历和照片、保存草稿；最终提交默认关闭。首次创建云表、自动记录申请，须是用户明确要求或已确认的初始化方案。

推荐提问合并为一条：“请提供简历路径、可选照片，并选择 Chrome＋Jev 或 Edge＋Playwright。是否创建私有飞书投递表？飞书操作选择浏览器（无需 MCP）还是已接入的飞书 MCP？”如果用户已明确要求自动建表，记录该授权，不再重复询问；已回答的项目不再问。

保存 `tracker.transport` 为 `browser` 或 `mcp`。示例中的 null 表示尚未选择，不能推断为 MCP 优先。用户选择浏览器时无需创建飞书开放平台应用或准备 App Secret。用户选择 MCP 但尚未接入时，说明所需连接能力，待其自行配置或明确要求协助接入；不自动安装或收集密钥。仅明确允许浏览器回退时设 `tracker.allow_browser_fallback: true`。后续任务复用选择，用户要求更换方式时更新配置并继续操作同一张表。

## 建立私人目录

使用用户指定配置目录，否则当前工作目录 `.resume-autofill/`。先检查是否已有配置、资料和 tracker 状态，不覆盖它们。写入 `config.json`，以 `examples/config.example.json` 为字段约定；示例中所有空路径均须按实际输入填充或保持 null。

配置保存简历/照片来源、浏览器偏好和非凭据配置。远程文件按[文件规则](files.md)缓存到私人目录；原始本地文件可直接引用，无需复制。提取资料写入 `profile.md`，事实注明来源，用户修正优先。不要照抄 `examples/profile.example.md` 的虚构事实。

跨聊天时，用户在同一工作目录继续即可自动发现配置。换工作目录/换工具时需给出配置路径；不能承诺任意新聊天都会自动定位旧私人目录。

## 飞书初始化

按所选方式执行 [feishu.md](feishu.md) 创建并验证表格。请求创建前把状态设为 `creating` 并保存本次 request_id；每完成一步立即保存已有表格 URL 及可获取的远端 ID，不能等所有步骤完成才保存。浏览器模式不为取得非必要的 ID 转用 MCP。

建议私人目录：

```text
.resume-autofill/
├── config.json
├── profile.md
├── tracker-state.json
├── applications.json
└── files/
```

`tracker-state.json` 保存初始化状态、远端 ID、表格 URL、字段映射和创建时间，不放访问令牌。`applications.json` 保存本地申请标识、远端 record_id 和待登记项，不默认保存完整表单、截图或整份简历。写状态用同目录临时文件再替换，保留未知字段；不把空配置覆盖到现有状态。

首次完成向用户报告私人配置路径和飞书链接。MCP 登录、OAuth、App Secret、Jev key 均由各工具的凭据管理处理；不要让用户把密钥粘贴到对话或仓库。
